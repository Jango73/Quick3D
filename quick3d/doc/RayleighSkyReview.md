# Review of commit b0bb3af - Physical Rayleigh sky and Environment settings

## Critical
- [x] `quick3d/source/render/C3DScene.h:428` stores `CSkyModel* m_pSkyModel` with manual `new`/`delete` in destructor, `resetEnvironmentToDefaults()`, and `setSkyModel()` instead of `QSP` shared ownership required by AGENTS.md, creating tripled delete logic that is exception-unsafe and leak-prone.
- [x] `quick3d/source/render/C3DScene.h:227,233` (`skyModelName()`, `skyModelId()`) and `quick3d/source/render/C3DScene.cpp:484` (`LOG_WARNING` in `setSkyModel()`) dereference `m_pSkyModel` without null-check while `CSkyModel::create()` returns `nullptr` for unknown names, so one bad `DEFAULT_SKY_MODEL` or XML value crashes the scene.
- [x] `quick3d/doc/Quick3DScene.xsd` defines `EnvironmentType` with both `<xs:sequence>` and `<xs:simpleContent>` in the same `complexType`, which is forbidden by the XSD specification, so the schema cannot validate any scene file containing `<Environment>`.
- [x] `quick3d/source/render/C3DScene.cpp:300-303` (`loadEnvironment()`) assigns `m_dOzoneAmount` directly from XML instead of calling `setOzoneAmount()`, bypassing the negative-value clamp enforced in the setter, `CAtmosphereOptics::computeExtinction()`, and `CRayleighSkyModel::setupUniforms()`, so a negative `OzoneAmount` enters the scene unchecked.
- [x] `quick3d/source/render/CGLWidgetScene.cpp:281,342,360` reads environment state via `pContext->scene()->skyModel()` / `ozoneAmount()` / `skyColor()` while executing as `this` (`CGLWidgetScene` inherits `C3DScene`), so when `pContext->scene() != this` the rendered uniforms and the computed sunlight tint silently diverge from the owning scene state.

## Major
- [x] `quick3d/resources/shaders/glsl1/FS_Standard.c` and `quick3d/resources/shaders/glsl4/FS_Standard.c` duplicate the exact same 67 added lines (`u_sky_model` uniforms, `rayleighSkyAt()`, modified `stars()`, `standardSkyAt()`), doubling the maintenance surface so every physics fix must be applied twice with no consistency check.
- [x] Kasten-Young coefficients `0.50572 / 6.07995 / 1.6364` are triplicated in `quick3d/source/utils/CAtmosphereOptics.h:43-45` and in `rayleighSkyAt()` of both `FS_Standard.c` variants, with only a `keep them in sync` comment as protection, guaranteeing silent CPU/GPU divergence on the next edit.
- [x] `dSinElevation <= 0.0 / > 1.0` input clamping is triplicated across `CAtmosphereOptics::computeAirmass()`, `CAtmosphereOptics::computeSunTransmittance()`, and `computeSunlightColor()` in `quick3d/source/render/CSunlightModel.h:26-34` instead of a single shared clamp helper.
- [x] `dOzoneAmount < 0.0` clamping is triplicated across `CAtmosphereOptics::computeExtinction()`, `CRayleighSkyModel::setupUniforms()`, and `C3DScene::setOzoneAmount()` instead of one validation at the input boundary (XML parsing / setter).
- [x] `quick3d/source/render/CGLWidgetScene.cpp:313-315,345-347,355-357` spells per-channel Beer-Lambert attenuation and fog/sun color scaling out as three `X/Y/Z` statements repeated at three call sites instead of using vector operators or a `CVector3`-level multiply helper.
- [x] `quick3d/source/render/C3DScene.cpp:280-303` repeats the same five-block `if (attributes()[...].isEmpty() == false) { m_X = ...toDouble(); }` pattern for `AtmosphereAltitude`, `FogMinimumDistance`, `UnderwaterFogDistance`, `SkyModel`, `OzoneAmount` instead of a generic `readDoubleAttribute()` helper.
- [x] `quick3d/source/render/C3DScene.h/.cpp` absorbs the whole environment responsibility (six new setters, eight new getters, five new members, `resetEnvironmentToDefaults()` + `loadEnvironment()`) instead of introducing a `CEnvironment` value object owned by the scene, violating single-responsibility and forcing `C3DScene` to act as god-object.
- [x] `quick3d/source/utils/CAtmosphereOptics.h:22` declares a class containing only `static inline` methods with no state, which must be a namespace, while `quick3d/source/render/CSunlightModel.h` does the opposite by naming a `Model` file that contains no class at all, only the free function `computeSunlightColor()`, breaking the `CSkyModel` hierarchy naming consistency.
- [x] `quick3d/source/render/CSkyModel.cpp:4` includes `CRayleighSkyModel.h` while `quick3d/source/render/CRayleighSkyModel.h:5` includes `CSkyModel.h`, creating a bidirectional base-derived coupling forbidden by AGENTS.md; the factory must move to a separate file or registry instead of living in the base class.
- [x] Shader uniform names (`u_sky_model`, `u_sun_direction`, `u_rayleigh_beta`, `u_rayleigh_scale_height`, `u_ozone_beta`, `u_ozone_amount`, `u_sky_exposure`) are hardcoded string literals split between `quick3d/source/render/CSkyModel.cpp:32` and `quick3d/source/render/CRayleighSkyModel.cpp:23-28` with no shared constants against the GLSL declarations, so a shader rename breaks C++ silently.
- [x] `quick3d/source/render/CGLWidgetScene.cpp:278` keeps pushing the legacy `u_sky_zenith_color` uniform while the `SKY_MODEL_PHYSICAL` shader path ignores it, leaving dead uniform traffic and a lingering confusion between `skyColor()` base color and the computed physical sky.
- [x] `quick3d/source/render/CSkyModel.h:30,42` exposes a raw-pointer factory (`static CSkyModel* create()`) and `quick3d/source/render/C3DScene.h:230` exposes `CSkyModel* skyModel()` mutably, allowing external code to `delete` or replace scene-owned state outside the `QSP` ownership chain.
- [x] `quick3d/source/render/C3DScene.cpp:249-270` implements `readEnvironmentColor()` as a `static` free function mutating scene members by `CVector3&` reference instead of a method of an environment object, breaking encapsulation to work around the missing `CEnvironment` class.
- [x] `quick3dtest/Quick3DTest.cpp` deletes the 56-line `Sky` color dialog without providing any `Environment` replacement UI, making `SkyColor` and all new environment settings XML-only and untestable interactively.
- [x] `quick3dtest/tests/CTestScene.cpp:testHorizonSkyHasNoGreenCastWithOzone` re-implements the production formula (`computeSunTransmittance` + `computeScatteringShare` + `computeExtinction`) inside the test instead of asserting against independent reference values, so the test mirrors the implementation instead of validating it.
- [x] `quick3d/source/base/CComponentLoader.cpp:40` unconditionally calls `pScene->resetEnvironmentToDefaults()` on every load while the `C3DScene` constructor already does it, hiding environment lifecycle inside the loader with an implicit double-initialization order dependency.
- [x] `quick3d/source/render/CSunlightModel.h:24` names its parameter `dSinElevation` but `quick3d/source/render/CGLWidgetScene.cpp:304,342` computes and passes `dCosZenith` (`sin(elevation) == cos(zenith)` is numerically equal but nominally opposite), misleading the next reader about which angle convention is expected.

## Minor

- [x] `quick3d/source/render/CEnvironmentDefaults.h` mixes true physical constants (Rayleigh beta, scale height, ozone beta, water attenuation) with scene configuration defaults (fog distances, ambient colors, exposure) in one flat macro list instead of separating physics from configuration.
- [x] `quick3d/source/render/CSunlightModel.h:5,11` includes `<cmath>` and `Angles.h` that the inline function never uses directly (all math delegates to `CAtmosphereOptics`), adding unneeded header coupling.

- [x] `quick3d/source/render/C3DScene.h:93-109,214-233` documents every new setter/getter with a bare `//!` marker and no `brief` text, adding no usable qdoc documentation despite the repository rule requiring compiling qdoc comments for public headers.
